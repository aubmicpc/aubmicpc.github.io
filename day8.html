A

Binary Search

Why searching the array is too slow

On Day 6 you searched an array by checking every element. Doing that for each query takes up to N × Q = 105 × 105 = 1010 operations, which is far too slow. We need a much faster way to answer each query.

Sorting

sort puts the elements of an array in increasing order:

vector<int> a = {1, 5, 4, 3, 2};
sort(a.begin(), a.end());
// a is now {1, 2, 3, 4, 5}

a.begin() and a.end() tell sort to sort the whole array. Sorting N elements takes about N × log2 N operations, which for N = 105 is under 2 × 106.

Binary search

Binary search is one of the most important algorithms in competitive programming. You'll use it on its own, inside other algorithms, and in problems that don't look like searching at all. It's worth understanding properly.

You already know the idea from a guessing game. Someone picks a number from 1 to 100, and after each guess they tell you “higher” or “lower”. Guessing 1, 2, 3, … could take 100 guesses. The smart strategy is to always guess the middle: 50 first, and if they say “higher”, you've ruled out 1 to 50 with one guess. Then 75, then 62, and so on. Every guess cuts the possibilities in half, so you never need more than 7 guesses.

A sorted array works the same way. Pick the middle element and compare it with X:

  • If it equals X, you've found it.
  • If it's smaller than X, then every element to its left is smaller too, because the array is sorted. X can only be to its right, so throw away the left half.
  • If it's bigger than X, then by the same reasoning X can only be to its left, so throw away the right half.

Then repeat on the half that's left, until you find X or nothing is left. This only works because the array is sorted. In an unsorted array, the middle element tells you nothing about where X is.

Writing it in code

Keep two indexes, lo and hi. They mark the part of the array that hasn't been thrown away yet: if X is in the array at all, it's somewhere between a[lo] and a[hi]. At the start that's the whole array, so lo = 0 and hi = n - 1.

int lo = 0, hi = n - 1;
bool found = false;
while (lo <= hi) {
    int mid = (lo + hi) / 2;
    if (a[mid] == x) {
        found = true;
        break;
    }
    else if (a[mid] < x) lo = mid + 1;
    else hi = mid - 1;
}

Throwing away the left half means moving lo to just after mid, and throwing away the right half means moving hi to just before it. mid itself is thrown away in both cases, since we already know it isn't X. That's also what guarantees the loop ends: the range gets smaller every step.

If X isn't in the array, the range keeps shrinking until lo passes hi. Here's how that looks for X = 6 in the sorted sample array {1, 2, 3, 4, 5}:

lohimida[mid]Next
04233 < 6, so lo = 3
34344 < 6, so lo = 4
44455 < 6, so lo = 5
54lo > hi, not found

Why it's so fast

Each step halves the range, so the number of steps is how many times you can halve N before reaching 1. That number is log2 N, and it grows incredibly slowly:

Array sizeChecking every elementBinary search
1001007
105100,00017
1061,000,00020
1091,000,000,00030

Doubling the size of the array adds just one more step. In this problem, each query takes at most 17 steps, so all 105 queries together take about 1.7 × 106 operations, instead of 1010.

Solution

Try the problem on Codeforces before revealing the solution.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, q;
    cin >> n >> q;
    vector<int> a(n);
    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }
    sort(a.begin(), a.end());

    while (q--) {
        int x;
        cin >> x;
        int lo = 0, hi = n - 1;
        bool found = false;
        while (lo <= hi) {
            int mid = (lo + hi) / 2;
            if (a[mid] == x) {
                found = true;
                break;
            }
            else if (a[mid] < x) lo = mid + 1;
            else hi = mid - 1;
        }
        if (found) cout << "found" << "\n";
        else cout << "not found" << "\n";
    }
    return 0;
}

Sort the array once, then answer each query with a binary search.

Each query starts with a word saying its type. A word is read into a string, and it can be compared with text in double quotes:

string type;
int x;
cin >> type >> x;
if (type == "lower_bound") {
    // ...
}

The built-in binary searches

C++ has binary search built in, as part of the Standard Template Library (STL). All three functions below only work on a sorted array, so sort it first.

binary_search returns true if X is in the array and false otherwise, which is exactly what you wrote by hand in problem A:

if (binary_search(a.begin(), a.end(), x)) cout << "found" << "\n";

lower_bound finds the first element that is greater than or equal to X, and upper_bound finds the first element that is strictly greater than X. Subtracting a.begin() turns the result into an index:

int i = lower_bound(a.begin(), a.end(), x) - a.begin();

If no such element exists, the index is n, one past the last element. In that case print -1; otherwise the answer is a[i].

For example, in the sorted array {1, 2, 3, 4, 5}, lower_bound of 3 gives index 2 (the 3 itself) and upper_bound of 3 gives index 3 (the 4). upper_bound of 5 gives index 5, which is n, so the answer is -1.

Solution

Try the problem on Codeforces before revealing the solution.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, q;
    cin >> n >> q;
    vector<int> a(n);
    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }
    sort(a.begin(), a.end());

    while (q--) {
        string type;
        int x;
        cin >> type >> x;
        if (type == "binary_search") {
            if (binary_search(a.begin(), a.end(), x)) cout << "found" << "\n";
            else cout << "not found" << "\n";
        }
        else {
            int i;
            if (type == "lower_bound") i = lower_bound(a.begin(), a.end(), x) - a.begin();
            else i = upper_bound(a.begin(), a.end(), x) - a.begin();

            if (i == n) cout << -1 << "\n";
            else cout << a[i] << "\n";
        }
    }
    return 0;
}

Sort the array, read each query's type, and call the matching built-in function. For lower_bound and upper_bound, an index of n means there is no such element.
