Basic Data Types

Data types

Every variable in C++ has a type, and the type decides what it can hold. These are the ones you'll use all the time:

TypeStoresRange
intInteger, 32 bitsabout ±2.1×109
long longInteger, 64 bitsabout ±9.2×1018
charOne character'a', '7', '>'
floatReal number, 32 bitsabout 7 significant digits
doubleReal number, 64 bitsabout 15 significant digits

So how do you choose? Look at the constraints in the problem. An int only goes up to about 2 billion, so if a number can get bigger than that, use long long. For decimals, just use double. float is less precise and you'll rarely need it.

Input with cin

cin is like cout in reverse: it takes values from the input and puts them into your variables, in the order you write them.

int n;
char c;
double x;
cin >> n >> c >> x;   // input: 42 z 2.5

It doesn't matter if the values are on one line or spread over several, cin just skips the spaces and newlines in between.

One thing that surprises people: by default, cout prints decimals with 6 significant digits, so longer numbers get cut short:

double a = 3.14159265, b = 14049.30493;
cout << a << " " << b << "\n";
Output 
3.14159 14049.3

This is usually fine, because problems that print decimals accept answers that are off by a tiny amount.

Solution

Try the problem on Codeforces before revealing the solution.

#include <iostream>
using namespace std;

int main() {
    int a;
    long long b;
    char c;
    float f;
    double d;
    cin >> a >> b >> c >> f >> d;
    cout << a << "\n" << b << "\n" << c << "\n" << f << "\n" << d << "\n";
    return 0;
}

Read every value into the right type and print them one per line. The only catch is b, which is too big for an int.

B

Digits Summation

Arithmetic

You have + - * / %, and most of them work the way you'd expect. The two to watch out for:

  • / between two integers throws away the decimal part, so 7 / 2 gives 3, not 3.5. If you want 3.5, make one of them a decimal: 7.0 / 2.
  • % gives you the remainder, so 7 % 2 is 1.

A trick you'll use a lot: % 10 gives you the last digit of a number, and / 10 chops it off.

int n = 4096;
cout << n % 10 << "\n";   // 6   (last digit)
cout << n / 10 << "\n";   // 409 (last digit removed)

Solution

Try the problem on Codeforces before revealing the solution.

#include <iostream>
using namespace std;

int main() {
    long long n, m;
    cin >> n >> m;
    cout << n % 10 + m % 10 << "\n";
    return 0;
}

Get the last digit of each number with % 10 and add them up. N and M can be as big as 1018, so they need to be long long.

Difference

Integer overflow

Every type has a maximum value. If a result goes past it, it overflows: the number wraps around and you get garbage, and C++ won't warn you about it.

int x = 100000;
cout << x * x << "\n";         // prints 1410065408, not 10000000000

long long y = x * x;           // still wrong: x * x is computed as int

The second line catches a lot of people. Since x is an int, C++ does the multiplication as an int first and only then stores it in y, and by then it has already overflowed. The fix is to make the variables themselves long long.

Also, * / % happen before + -, same as in math. If you're not sure, add parentheses.

Solution

Try the problem on Codeforces before revealing the solution.

#include <iostream>
using namespace std;

int main() {
    long long a, b, c, d;
    cin >> a >> b >> c >> d;
    cout << "Difference = " << a * b - c * d << "\n";
    return 0;
}

A × B can be as big as 1010, which doesn't fit in an int, so use long long for everything. And print Difference = exactly as written, spaces included.
