A

Three Numbers

Nested loops

A loop can go inside another loop. For every step of the outer loop, the inner loop runs all the way through:

for (int x = 0; x <= 2; x++) {
    for (int y = 0; y <= 2; y++) {
        cout << x << " " << y << "\n";
    }
}
// prints 0 0, 0 1, 0 2, 1 0, 1 1, 1 2, 2 0, 2 1, 2 2

This goes through every pair (x, y), so the inner line runs 3 × 3 = 9 times. With three nested loops you get every triple, which is the obvious way to try all values of X, Y and Z and count the ones that add up to S.

Counting the operations

Remember the rule of thumb from Day 3: about 107 operations is fine, and more than 108 will never pass. Three nested loops from 0 to K run about K3 times, and with K = 3000 that's 2.7 × 1010. Far too slow.

But the third loop isn't needed. Once X and Y are chosen, Z has to be S − X − Y, so there's only one value to check instead of K + 1. The only question is whether that value is allowed, meaning 0 ≤ Z ≤ K.

That leaves two nested loops, about K2 = 9 × 106 operations, which is fast enough.

Solution

Try the problem on Codeforces before revealing the solution.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int k, s;
    cin >> k >> s;
    int count = 0;
    for (int x = 0; x <= k; x++) {
        for (int y = 0; y <= k; y++) {
            int z = s - x - y;
            if (z >= 0 && z <= k) count++;
        }
    }
    cout << count << "\n";
    return 0;
}

Try every X and Y, compute the only Z that works, and count it if it's between 0 and K.

B

Sum of Consecutive Odd Numbers

Putting the numbers in order

X can be bigger than Y, like in the second sample (10 4). A loop from X up to Y would then never run. The easiest fix is to make sure the smaller number comes first, and swap exchanges the values of two variables:

if (x > y) swap(x, y);
// now x <= y

The numbers strictly between them are then x + 1 up to y - 1. If there are none, such as between 5 and 6, the loop simply doesn't run.

Checking for odd numbers

A number is even when it divides by 2 with no remainder, and odd otherwise. So i % 2 == 1 means i is odd, for any number that isn't negative.

Solution

Try the problem on Codeforces before revealing the solution.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        int x, y;
        cin >> x >> y;
        if (x > y) swap(x, y);
        int sum = 0;
        for (int i = x + 1; i < y; i++) {
            if (i % 2 == 1) sum += i;
        }
        cout << sum << "\n";
    }
    return 0;
}

Swap so that X ≤ Y, then add up the odd numbers from X + 1 to Y − 1. Declare sum inside the test case loop so it starts at 0 for each test case.

C

Digits

The do–while loop

Taking digits off from right to left is exactly what the loop in Day 4's Palindrome did, except this time each digit is printed instead of added to a reversed number. Because the digits are printed one by one, the zeros in 1200 show up as they should.

There is one catch. For N = 0 the answer is 0, but the condition n > 0 is false from the start, so a while loop prints nothing. A do–while loop checks its condition after each repetition instead of before, so its body always runs at least once:

do {
    cout << n % 10 << " ";
    n /= 10;
} while (n > 0);

Note the semicolon after while (n > 0). It's required here, unlike in a normal while loop.

Extra spaces

The loop above prints a space after every digit, including the last one. That's fine: Codeforces ignores spaces at the end of a line, so you don't need any extra code to avoid them.

Solution

Try the problem on Codeforces before revealing the solution.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        int n;
        cin >> n;
        do {
            cout << n % 10 << " ";
            n /= 10;
        } while (n > 0);
        cout << "\n";
    }
    return 0;
}

Print the last digit and remove it until nothing is left. The do–while makes sure N = 0 still prints 0. End each test case with a new line.

D

GCD

Checking divisibility

i divides a exactly when the remainder is 0, so the check is a % i == 0. A common divisor of A and B has to pass the check for both numbers:

if (a % i == 0 && b % i == 0) {
    // i divides both a and b
}

A common divisor can't be bigger than the smaller of the two numbers, so the candidates are 1 up to min(a, b).

Counting down and break

We want the greatest common divisor, so go through the candidates from largest to smallest. The counter starts high and decreases with i--. The first common divisor found is the answer.

Once it's found, there's no reason to keep looping. break ends the loop immediately and continues after it:

for (int i = min(a, b); i >= 1; i--) {
    if (a % i == 0 && b % i == 0) {
        cout << i << "\n";
        break;
    }
}

The loop always finds an answer, because 1 divides every number.

Solution

Try the problem on Codeforces before revealing the solution.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int a, b;
    cin >> a >> b;
    for (int i = min(a, b); i >= 1; i--) {
        if (a % i == 0 && b % i == 0) {
            cout << i << "\n";
            break;
        }
    }
    return 0;
}

Count down from the smaller number and stop at the first number that divides both A and B.

E

Divisors

Finding every divisor

Every divisor of N is between 1 and N, so go through all of them and use the same check as in GCD, n % i == 0. Counting upwards from 1 means the divisors come out in ascending order on their own.

N is at most 104, so that's at most 104 checks, which is well within the time limit.

Solution

Try the problem on Codeforces before revealing the solution.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    for (int i = 1; i <= n; i++) {
        if (n % i == 0) cout << i << "\n";
    }
    return 0;
}

Check every number from 1 to N and print the ones that divide N.
