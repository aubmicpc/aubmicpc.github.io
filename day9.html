How scoring works

OI-style problems

Today's problems are set up in OI style, which is how the AUB contest will be run. This is different from the official ICPC contest, where a problem only counts if your solution passes every test.

In OI style, each problem is worth 100 points, split into subtasks. Each subtask has its own group of tests with extra limits, such as a smaller N or a special case that's easier to handle. The Scoring section of each statement lists the subtasks, their limits, and how many points each is worth.

This means you can earn points on a problem even if you can't solve all of it. If you don't see the full solution, a simpler solution that only handles the smaller subtasks is still worth submitting.

Points don't add up by themselves

You get a subtask's points only if your solution passes every test in that subtask. Failing even one test gives you 0 for that subtask.

The points next to a subtask are what that subtask alone is worth, and each subtask is judged separately. Getting a subtask does not mean you also get the subtasks before it. Your score on the problem is the sum of the subtasks you actually passed.

For example, Magic Cells (problem C) has four subtasks:

SubtaskLimitsPoints
1N = M = 210
2N, M ≤ 100, no magic cells24
3N, M ≤ 100, exactly two magic cells27
4N, M ≤ 10339

A solution that passes all four gets 10 + 24 + 27 + 39 = 100. A solution that only works when there are no magic cells passes subtask 2 and gets 24 points. It doesn't get subtask 1's 10 points just because subtask 1 comes first: subtask 1 can have magic cells, so that solution fails some of its tests.

Submitting more than once

You can submit a problem as many times as you like, and your score on it is the highest score of any single submission. Scores from separate submissions are never added together.

For example, if one submission to Magic Cells passes only subtask 2 for 24 points, and another passes subtasks 1 and 3 for 37 points, your score is 37, not 61. To get 100, one submission has to pass all four subtasks.

A

Missing Area

Choosing the right type

The four parts make up the whole circle, so A + B + C + D = X, and the answer is D = X − A − B − C.

The two subtasks only differ in how big the numbers are. In subtask 1 they are at most 103, so an int works. In subtask 2 they can reach 1018, which is far beyond an int but still fits in a long long (up to about 9.2 × 1018).

A solution using int would get 49 points. Using long long gets all 100.

Solution

Try the problem on Codeforces before revealing the solution.

#include <bits/stdc++.h>
using namespace std;

int main() {
    long long x, a, b, c;
    cin >> x >> a >> b >> c;
    cout << x - a - b - c << "\n";
    return 0;
}

Subtract the three known areas from the whole circle, using long long for subtask 2.

B

Unique Game

The largest and the second largest

Find the answer in two passes over the array. The first pass finds the largest value. The second pass finds the largest value that is strictly smaller than it:

long long second = LLONG_MIN;
for (int i = 0; i < n; i++) {
    if (a[i] < first) second = max(second, a[i]);
}

LLONG_MIN is the smallest possible long long, so any value in the array replaces it. Checking a[i] < first skips every copy of the largest value, which is why the sample 4 4 1 1 2 gives 2 and not 4.

What each subtask adds

Each subtask adds one more thing your solution has to handle:

  • Subtask 1: only two cards, so the answer is just the bigger one and then the smaller one.
  • Subtask 2: more cards, so you need a loop.
  • Subtask 3: values can repeat and can be negative. A solution that just takes the two biggest cards fails on 4 4 1, and one that starts second at 0 fails when all values are negative.
  • Subtask 4: values up to 1015, so they need a long long.

Solution

Try the problem on Codeforces before revealing the solution.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> a(n);
    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }

    long long first = LLONG_MIN;
    for (int i = 0; i < n; i++) {
        first = max(first, a[i]);
    }

    long long second = LLONG_MIN;
    for (int i = 0; i < n; i++) {
        if (a[i] < first) second = max(second, a[i]);
    }

    cout << first << "\n" << second << "\n";
    return 0;
}

Find the largest value, then the largest value strictly smaller than it. Both are long long for subtask 4.

C

Magic Cells

Counting steps in a grid

Since you can only move down or right, every path from (1, 1) to a cell (i, j) takes exactly the same number of steps: i − 1 steps down and j − 1 steps right, so (i − 1) + (j − 1) in total. The order doesn't matter.

Without magic cells, that's the whole problem: reaching (N, M) takes (N − 1) + (M − 1) steps. This solves subtask 2.

Using the magic cells

Every magic cell is a shortcut: once you reach it, you are at (N, M) with no more steps. So the answer is the smallest of:

  • (N − 1) + (M − 1), walking all the way, and
  • (i − 1) + (j − 1) for every magic cell (i, j).

In the sample, the magic cell (3, 1) takes only 2 + 0 = 2 steps to reach, which is the answer.

With 0-indexed loops over the rows and columns, the steps to reach cell [i][j] are simply i + j. You don't even need to store the grid: check each value as you read it.

Solution

Try the problem on Codeforces before revealing the solution.

#include <bits/stdc++.h>
using namespace std;

int main() {
    int n, m;
    cin >> n >> m;
    int ans = (n - 1) + (m - 1);
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < m; j++) {
            int cell;
            cin >> cell;
            if (cell == 1) ans = min(ans, i + j);
        }
    }
    cout << ans << "\n";
    return 0;
}

Start with the steps to walk all the way to (N, M), and lower the answer whenever a magic cell is closer.

D

Back to School

Trying every pair

The direct approach is to try every pair of different indexes with two nested loops. Starting j at i + 1 makes sure i and j are never equal, and checks each pair only once:

for (int i = 0; i < n; i++) {
    for (int j = i + 1; j < n; j++) {
        if (a[j] == x - a[i]) good = true;
    }
}

That's about N2 / 2 checks per test case. For N ≤ 100 it's instant, so this passes subtasks 1 and 2 for 40 points. For N = 105 it's 5 × 109 checks per test case, which is far too slow for subtask 3.

Binary search for the partner

For each element a[i], there's only one value it can be paired with: x - a[i]. So instead of looping over every j, sort the array and use binary search from Day 8 to check whether that value is there.

To keep j different from i, only search the part of the array after index i. a.begin() + i + 1 means “start at index i + 1”:

if (binary_search(a.begin() + i + 1, a.end(), x - a[i])) good = true;

Searching only to the right is enough: if the pair is at indexes j < i, it was already found when the loop was at j. It also stops an element from being paired with itself: for {1, 2, 5} and X = 4, the partner of 2 would be 2, but there's no second 2 after it, so the answer is correctly NO.

Now each test case takes about N × log2 N ≈ 1.7 × 106 operations, which passes all three subtasks.

Fast input and output

Keep these two lines at the top of your main function. They speed up cin and cout, which helps with big tests like the ones in this problem:

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    // the rest of your code
}

Solution

Try the problem on Codeforces before revealing the solution.

#include <bits/stdc++.h>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int t;
    cin >> t;
    while (t--) {
        int n, x;
        cin >> n >> x;
        vector<int> a(n);
        for (int i = 0; i < n; i++) {
            cin >> a[i];
        }
        sort(a.begin(), a.end());

        bool good = false;
        for (int i = 0; i < n; i++) {
            if (binary_search(a.begin() + i + 1, a.end(), x - a[i])) {
                good = true;
                break;
            }
        }

        if (good) cout << "YES" << "\n";
        else cout << "NO" << "\n";
    }
    return 0;
}

Sort the array, then for each element binary search for x - a[i] among the elements after it. The first two lines of main make reading the input fast.
